# 产品范围与实施计划

更新：2026-10-03。状态：讨论确认的目标设计，尚未代表功能全部实现。

本文汇总 Q1–Q67 的已确认选择，取代旧路线图中与之冲突的版本范围和依赖顺序。接口细节见[可观测性契约](native-agent-tui-observability.md)，现有功能与历史测试记录见[实施状态](implementation-status.md)。Core/UI/workflow 文档继续规定模块边界；GitHub Issue 记录剩余任务。

## 1. 产品价值与发布范围

个人开发者应能随时回答：现在发生什么、谁在等谁、最后可靠证据是什么、需要我做什么。进程活着不能证明任务推进。

| 阶段 | 承诺 | 范围 |
| --- | --- | --- |
| V1 / `0.1.0-alpha`（计划版本） | 可靠单 agent + 观察恢复 | 本地 Codex、审批/输入、中断/停止、活动证据、Attention、JSONL/Python 消费者、journal 回放和脱敏导出 |
| V2 | 可解释多 agent | 一个根工作流、1–3 个直属 child、Gate/交付报告、任务依赖和调度操作 |
| 后续候选 | 反馈驱动扩展 | 更多并发、多 provider、远程协作、插件市场、Web companion；当前不承诺交付日期 |

本地 HEAD `4ef5716` 的实施记录已包含原生 child、Gate 和 F3 代理视图。V1/V2 是支持和验收范围，不要求删除已有功能。现有 child/Gate 路径保持回归；完整 scheduler 和更多并发不阻塞单 agent Alpha。多 child fixture 可提前验证观察模型，不宣称 V2 已可用。

工具执行继续由 app-server 承担。默认 `workspace-write + on-request`，启动时显示最终策略；不自动扩大权限。UI 英文默认，中文文档先行，后续补中文文案；中文/emoji 输入和显示从第一版就必须可用。

## 2. 兼容、恢复与隐私

- 先支持一个锁定且经过真实验证的 Codex 版本；现有实施记录的基线为 0.159.2，不表示最新版本。维护兼容表和 schema fixture；升级必须手动审核并运行回放和 smoke test，不自动下载或切换 Codex。
- 在已验证版本内探测能力。可选信息缺失显示 unavailable；缺少启动、审批或终态等必需能力则禁止执行。未验证版本不承诺可写执行兼容；未来扩展范围需新增证据。
- journal 默认保存在操作系统用户数据目录，以工作区与 session 隔离；默认上限 30 天或 500 MB，先达到者触发淘汰。不得删除仍需恢复的活动 control 记录；无法安全腾挪时显示持久化错误并阻止新执行。
- journal 保存脱敏事件与状态摘要。回放只恢复该投影，无法重建被排除的原 prompt、secret、完整对话或原始工具输出。不存在的内容显示 unknown，不承诺完整 transcript。
- 恢复不启动模型、不接管旧进程、不重发审批。用户选择重试时创建新 attempt/generation，明确旧外部副作用可能已发生；任务正文未保留时要求重新输入或用户提供任务文件。
- 默认无诊断上传。可选遥测必须由用户主动开启，首次设置入口默认关闭，字段固定并可预览/撤销。接收服务未定义前只提供本地诊断和手动导出，不阻塞 Alpha。终端提示音/桌面通知同样可选且默认关闭，只发脱敏摘要。

## 3. 依赖与 Issue 映射

编号用于追踪，不表示所有工作严格串行。S2.5 拆成内存证据和持久流两部分，解决它依赖 journal、而 journal 原本排在最后的问题。

```text
S0 → S1 → S2 → S2.5a 内存活动证据、注意级别、fake/Python 契约
           ├→ S3 / S4 传输、审批加固 ───────────────┐
           └→ S9a journal/schema/回放 → S2.5b 持久 JSONL ┤
S2.5a + S4 → S7a 投影 → S8a 状态/请求操作          ├→ Alpha
S9a → S9b 脱敏导出、观察恢复                      │
S10a CI 从 S0 开始；S10b 汇总发布门禁 ────────────┘
Alpha 基线 + 现有 Gate 回归 → S5 / S6 → S7b / S8b → V2
```

| --- | --- | --- |
| #2 S0 | 当前实现、文件所有权、基线与回归记录 | 核对现有 Gate 与 55 项历史测试记录，重新实跑才可报告最新通过数 |

| #4 S2 | 单一 Core、RPC/生命周期、活动输入接口 | execution/activity/attention 分离；版本、事件、进展序号各有语义 |
| #13 S2.5 | a：证据/时钟；b：JSONL 和 Python 消费者 | b 依赖 #10 的持久化基础；真实启动和审批安全依赖 #5/#6 |
| #5 S3 | 有界传输、控制事件顺序、退出清理 | 慢消费者、过载、EOF、Windows 清理竞态，不承诺无限缓存 |

## 4. Alpha 门禁与试用

必须通过 fmt、check、clippy、test、release build；CI 使用确定性的 fake/replay 测试，发布前记录锁定 app-server 的真实 smoke test、Windows 终端/进程清理，以及 JSONL/Python 消费者测试。必需测试的环境失败不能当作通过：修复后重跑，或将该平台明确列为未支持。

第一条观察回归：父等待 child，child 静默跨阈值后恢复；两端显示相同等待目标、turn/generation、最近证据和 attention；新证据只清除对应活动的静默提示，不能释放 Gate。Alpha 可通过 fake replay 和已有 Gate 路径验证；V2 再验证 1–3 child 的真实并发。

| 试用指标 | 收集方式 / 判断 |
| --- | --- |
| 状态正确性 | fixture 中重复副作用、伪造完成、静默触发执行均为 0；现有 Gate 窗口零父请求 |
| 状态理解速度 | 记录用户能否在 5 秒内指出当前活动、等待对象和所需动作；目标值，不伪报已有结果 |
| 审批效率 | 详情可达，简单决策目标最多两步；不能为减少步数隐藏必要信息 |
| 任务完成率 | 固定真实开发任务集，报告成功数/总数及版本、环境、失败类别 |
| 观察恢复率 | 回放正确重建脱敏事实的 session 数/故障注入总数；新 attempt 成功率单列 |
| 现场可复现率 | 导出 fixture 可复现状态问题数/已报告问题数；不等同于复现外部副作用 |

试用包含工具调用、审批、长时间静默、失败/断连、恢复；child 场景标注当前实验范围。反馈模板记录任务类型、状态误判、缺少的证据、等待原因和用户采取的动作。尚无实测数据，不预设任务完成率的发布百分比。

## 5. 与先前讨论的可执行性澄清

stdout 不能重新附着为另一个进程的订阅连接；`--since` 指定 session journal 的只读回放。普通启动先发快照，回放先发游标处基线、补事件、再发最新快照。有限内存不能承诺永久保存离线慢消费者的全部消息：持久化、显式缺口和失败必须可见。上述边界详见[接口契约](native-agent-tui-observability.md)。

执行结果、历史测试记录与计划分别维护。当前更新不表示 ActivitySnapshot、JSONL CLI、journal 或新发布版本已经实现。
