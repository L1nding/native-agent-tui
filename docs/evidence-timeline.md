# 实时证据时间线

更新：2026-10-03。

## 浏览和定位

`Ctrl+T` 打开 Core 已确认的活动证据：轮次、输出计数、工具、请求、等待关系和执行终态。顶部继续显示当前执行状态、注意级别和待操作数量；事件详情显示事件发生时的状态，两者时间范围不同。

| 按键 | 操作 |
| --- | --- |
| ↑/↓、j/k、n/N | 选择前一条/后一条证据 |
| Home / End | 选择当前过滤结果首条/末条 |
| PageUp / PageDown | 滚动事件详情或帮助 |
| Tab | 当前线程 → 已确认子树 → 根到当前线程的路径 → 全部 |
| F6 | 切换生命周期、输出、工具、请求、等待类别 |
| F7 | 切换事件当时的执行状态；Unknown 单独显示 |
| F8 | 仅显示关联当前待回答请求的证据 |
| `/` / Ctrl+F | 编辑元数据查询；Enter 应用 |
| Ctrl+T（面板内） | 编辑精确 turn ID；Enter 应用 |
| b / B | 添加或移除书签 / 只看书签；其他过滤仍生效 |
| Enter | 定位仍保留的 Agent 消息或当前请求投递 |
| F1 / Esc | 帮助 / 关闭时间线并保留草稿和书签 |
| F2、F3、F4、F10、F11 | 返回对应实时面板 |
| F12 | 关闭时间线，进入历史观察；再次 F12 返回 |

查询为区分大小写的 Unicode 字面文本，范围是事件、身份、工具类别和等待目标等元数据。任务、秘密答案、消息正文和原始工具输出不参与此查询；消息正文使用已有 `Ctrl+F` 对话搜索。编辑查询时，b、B、n 等普通字符仍作为输入。

Enter 只定位内容，不回答请求、不提交任务。审批快捷键和提交键在时间线中没有执行作用；明确的 `Ctrl+C` 中断根任务、`Ctrl+Q` 退出仍可用。原输入及秘密表单草稿独立保存。

## 身份、顺序和保留范围

Core 的 Observer 在接受有效证据时归档冻结的活动身份、状态、item、工具类别、完整请求引用及等待目标。重复、空增量、旧轮次、计时器和阈值配置均不新增证据。工具结束仍保留 item ID；等待对象绑定轮次或进入终态时，归档更新后的目标。

这里的序号是 **Core 接受证据的顺序**，不是原始 RPC 的 ingress 序号，也不是 journal 游标。同一外部事实可以分别推进工具/请求活动和所属轮次活动，因此出现不同 scope 的两条证据是正常现象。

实时归档最多 512 条、256 KiB 事件元数据。快照共享不可变条目；更新最多复制 512 个 Arc 引用，不在观察 tick 复制全文。超限从最早条目淘汰；单条元数据超过预算则整条不保留，绝不裁剪身份后关联另一个对象。界面显示实际保留范围、已接受高水位和缺失条数，范围可能有缺口。

选择绑定 session 和证据序号；淘汰或被过滤后要求重新选择，不自动跳到另一个审批。请求定位校验 RPC ID、thread、turn 和 `received_seq`，同 ID 的新投递不能接收旧事件的操作。

书签最多 64 条、64 KiB 元数据，只存于当前 TUI。事件淘汰后，书签保留原始元数据并标明内容已淘汰；缺失内容禁止打开。书签不保存秘密或正文，不进入 journal、JSONL、历史恢复或导出。
