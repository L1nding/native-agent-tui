# 实时对话搜索

## 使用

`Ctrl+F` 打开独立搜索编辑区，保留任务和秘密答案草稿。输入中文、emoji 或其他文本后按 `Enter` 搜索；结果模式用 `Up/Down` 或 `N/n` 选择前后命中，再按 `Enter` 定位对话中的原消息。匹配行以颜色强调；搜索详情同时显示 `⟦匹配文本⟧`、角色、线程、轮次、item 和 UTF-8 字节位置。`Esc` 关闭搜索并保留原输入草稿。

| 搜索内按键 | 动作 |
| --- | --- |
| Ctrl+F / 结果模式的 `/` | 编辑查询 |
| Ctrl+T | 在查询与精确 turn ID 字段之间切换；留空 turn 字段表示全部轮次 |
| Tab | 当前线程 → 当前子树 → 根到当前代理的路径 → 全部代理 |
| F6 | 全部角色 → 用户消息 → 代理消息 |
| F7 | 全部消息 → 流式 → 完整消息 → 被裁剪的消息 |
| Enter | 编辑模式执行搜索；结果模式定位当前命中 |
| r | 结果模式刷新到当前保留快照 |
| PgUp/PgDn / Ctrl+Home/End | 逐行滚动详情 / 跳到首尾 |
| F1 | 打开或关闭搜索帮助；窄屏可逐行查看全部按键 |
| F2 | 关闭搜索并打开当前请求详情 |
| Ctrl+C / Ctrl+Q | 明确中断根轮次 / 退出并清理 |

搜索字段使用 grapheme 编辑和 Unicode 显示宽度。普通输入框中的 `/` 继续作为输入字符；不会把路径或任务内容当成全局快捷键。终端提供 `Event::Paste` 时，多行内容在搜索字段内转换为空格，不解释为快捷键；原生终端粘贴的限制见验证记录。

## 搜索范围与身份

搜索读取 Core 当前保留的对话投影，包括用户任务正文和代理消息。它采用区分大小写的字面匹配，不解释正则表达式。空查询返回零命中。turn 过滤精确匹配；尚未绑定轮次的用户消息显示 `unbound`。

子树和关联路径只沿 Core 已确认的父子 thread 关系构建，不用 path 名称推测归属。全部代理范围保留 Core 消息顺序。查询不读取工作区文件、工具参数或答案草稿，也不从脱敏 journal 重建已排除的完整对话。

结果固定在查询时的快照。刷新后按线程、轮次、item、角色与字节范围保留仍存在的选中项；不按变化后的屏幕行号定位。打开结果前检查当前消息身份和完整文本是否仍一致；更新或淘汰时显示原因，需显式刷新。窗口变化重新计算匹配行位置；定位后的普通翻页从该位置继续。

顶部执行阶段、Core attention 和待操作信息持续更新，搜索不会冻结真实执行。搜索内的审批快捷键不会回答请求；通过 F2 回到请求表单后才能操作。

## 有界执行与隐私

Core 对话上限为 128 条、256 KiB，每条正文最多 32 KiB。每个搜索字段最多 1024 UTF-8 字节；一次最多保留 512 个命中，另外显示本次保留范围内的准确匹配总数。达到结果上限时提示缩小查询、turn、角色或范围。历史或消息被裁剪时明确显示范围不可用。

一个独立异步任务扫描只读快照，并在消息及密集匹配之间让出执行。watch 通道只保留最新查询；新查询和关闭面板取消旧扫描，结果按查询序号接收。关闭时释放结果快照，UI 退出时 join 搜索任务。搜索没有 Core 命令或 app-server 接口。

查询、结果、位置和草稿只在 UI 内存中；journal、JSONL、历史和脱敏导出不保存它们。秘密答案不被复制到查询，搜索时也不会显示原输入区。

## 验证范围

九项搜索回归覆盖 Unicode 字节位置、组合字符/emoji 宽度、四种关联范围、turn/角色/消息状态过滤、命中与字段上限、旧扫描取消及快照释放、过期结果、秘密草稿和 Core/Gate 无命令副作用。额外覆盖同一批键盘事件中先改过滤器再按 Enter：查询尚未投递也立即禁用旧命中，旧查询序号不能替换新结果。TestBackend 检查 30×10、60×20、80×24、100×30、120×40、160×50 的帮助可达、无秘密草稿、命中定位与 resize 后翻页。

最终 `python scripts/verify.py --live` 全部通过：169 项默认 Rust 测试、八项真实 Codex 检查与全部原生夹具；fmt/check/clippy/doctest/release 通过。

Windows ConPTY 配合假 app-server 验证 Ctrl+F、中文查询、前后命中、范围/角色/turn 过滤、帮助首尾滚动、Enter 定位、中文/emoji 草稿恢复，以及 F2 返回审批。搜索前后 RPC 完全相同，根启动数为 1，原始消息数、接受证据数和各活动 progress_seq 不变。查询标记与草稿未进入 journal。随后明确 cancel、退出，确认只有一个审批回答、零根中断 RPC；进程身份检查通过，只读回放确认清理、journal 关闭、Interrupted 和脱敏结果。

本次 ConPTY 多行 bracketed-paste 转义注入只在查询中显示首行，不能视为 `Event::Paste` 或系统剪贴板的原生验收。已提交中文/emoji 键盘文本通过；Windows Terminal、Orca、IME 预编辑及多行粘贴路径需继续核查。

该功能搜索现有实时对话；完整事件时间线、书签、工具输出搜索、历史 journal 搜索和发布任务集仍有独立验收范围，Alpha/V2 完整交付尚未完成。
